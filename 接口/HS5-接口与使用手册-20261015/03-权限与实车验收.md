# 权限、只读诊断与实车验收

本次只整理资料与本地验证，未连接车机、发送车控/安装/休眠请求、授予权限、刷机或部署。

## 权限不是统一开关

| 层次 | 示例 | 正确核对方式 |
| --- | --- | --- |
| Manifest normal | Android9 BLUETOOTH/BLUETOOTH_ADMIN、Wi-Fi、网络权限 | APK是否声明、目标固件是否定义、已安装包实际授予状态 |
| runtime/dangerous | RECORD_AUDIO、定位；该 CarService 的 CAR_SPEED | 应用声明、当前用户授权、拒绝/撤销行为；只请求实际需要的功能 |
| 特殊访问/AppOps | SYSTEM_ALERT_WINDOW、WRITE_SETTINGS、Usage Access | 相应 Settings能力/AppOps；不按普通运行时授权理解 |
| signature/privileged | CONTROL_CAR_CLIMATE/DOORS/WINDOWS/SEATS、CAR_VENDOR_EXTENSION、CAR_DISPLAY_IN_CLUSTER | 定义方签名、privileged安装与固件allowlist等实际条件；Manifest声明不等于获得 |
| signature | BIND_CAR_INPUT_SERVICE、BIND_INSTRUMENT_CLUSTER_RENDERER_SERVICE、INJECT_EVENTS | 对应签名/受支持的系统架构，不能靠普通pm grant取得 |
| development | DUMP、WRITE_SECURE_SETTINGS在该固件的特殊标志 | 是否声明、固件定义、实际允许的ADB授予机制；不可外推到所有signature权限 |
| Binder服务端 | Qisi Adapter、QisiSystemService、厂商安装服务 | 组件绑定条件、调用者校验、方法结果；AAOS权限和OEM Binder条件独立 |
| Linux/SELinux/HAL | /dev/i2c-*、Binder/HwBinder、FM1388/RPC | 进程uid/domain、设备label、DAC、完整有效策略及目标方法检查 |

平台签名、system shared UID、priv-app目录、privapp-permissions、default-permissions、AppOps和SELinux分别解决不同条件。把APK放进系统目录不自动得到system UID或任意硬件权限。默认运行时授权XML也不自动设置悬浮窗AppOps。

AOSP仪表renderer按配置组件绑定，不是任意App声明service就可注册。`CAR_DISPLAY_IN_CLUSTER`、`CAR_INSTRUMENT_CLUSTER_CONTROL` 是signature|privileged；默认renderer字符串也不能证明该组件已安装和正在使用。

3222 vendor策略对FM1388/RPC有 `untrusted_app_all` 查找和Binder调用例外。因此需按接口检查，不采用“所有HAL普通App均不可访问”的泛化判断。单条allow也不能单独证明业务执行成功。

## 手动运行只读诊断

连接用户授权调试的车机后，可在电脑执行：

```sh
python3 tools/hs5_diagnostics.py --package com.shilapi.xcertplay.hs5 --output diagnostics/local-hs5.json
```

多设备时加 `--serial <本机adb设备标识>`；脚本不把该标识写进报告。DiPlay用 `--package com.shihab.diplay`。脚本只读取白名单属性、选定服务名、目标包权限/版本、AppOps及导航混音设置；不读取VIN/PDSN、Wi-Fi密码、认证文件、联系人或配对材料。它不会自动执行Binder车控，也不改变权限/系统设置。报告在本地生成，分享前仍按用途选取内容。

需要进一步现场定位时，按问题选取只读信息：

| 问题 | 建议读取 | 解释限制 |
| --- | --- | --- |
| 服务是否存在 | service list中的目标名字、dumpsys package的相关组件 | 注册存在不等于方法可调 |
| 当前安装身份 | dumpsys package的uid、签名来源、requested/granted权限；ps -AZ相关进程 | shell身份不同于App身份 |
| 副屏 | dumpsys display的display名称/尺寸/状态 | 不输出完整无关设备信息；显示存在不等于仪表像素已到达 |
| 音频 | audio focus、policy中当前usage/route与App会话诊断 | 不采集通话内容；请求焦点不等于最终听感 |
| 无线 | 目标P2P组主/连接状态和频率、蓝牙scan mode广播 | 不导出完整Wi-Fi dump或SSID密码；accepted不等于实际连接 |
| 车辆读取 | 本App快照状态、字段原值/时间戳、错误类型 | 不记录PDSN实际内容；单位未核就保留RAW |

本交付不附无界 `service call` 指令，也不提供全局关闭SELinux、越权grant或扫描未知事务号的步骤。现场检查应从已审核的只读getter开始，控制测试由明确用户操作触发。

## 实车验收记录格式

每次记录：车机/仪表固件版本，App包名/versionCode/APK SHA-256，平台匹配结果，相关能力/权限结论，动作时间，原始应答，新反馈时间/内容，原厂屏幕或物理结果，中断后的清理/恢复。PDSN只记“车型前缀匹配/不匹配”，不保存完整标识。

状态统一用“待验收/通过/失败/不支持/条件不足”，没有测试的不写通过。服务ACK、界面变化、物理执行和自动化测试各自记录。

| 领域 | 最小验收动作 | 接受条件 | 本次状态 |
| --- | --- | --- | --- |
| 身份/绑定 | 冷启后绑定根与目标模块 | 实际descriptor匹配；拒绝权限能如实显示 | 待实车 |
| 只读状态 | 原厂操作开灯、门/尾门等并对照 | 原始值、回调/轮询一致；无效码不变成0 | 待实车 |
| 单位 | 静态/行驶场景与原厂值对照 | 车速、油量、胎压、油耗完成单位/缩放闭环 | 待实车 |
| 车型/EOL | 读取判型和热/通风支持结论 | 本车条件匹配；缺配置禁止控制 | 待实车 |
| 空调开关 | 用户明确触发关/开各一次 | 下发1/2；ACK之外有新反馈与真实状态 | 待实车 |
| 温度/风量/模式 | 合法范围边界和典型值 | float类型正确、0.5°C步进、模式和原厂显示一致 | 待实车 |
| AUTO/A/C/同步/除霜/循环 | 每项单独操作并复原 | 下发与回读编码区分；循环0不当作已知功能 | 待实车 |
| 座椅 | 两座位逐项关/低/中/高 | 命令1..4、回读0..3；无能力不下发 | 待实车 |
| 连接时效 | 服务断开/重连、延迟回调 | 立即失效旧状态、超过5秒不显示为当前值、旧代回调无污染 | 待实车 |
| 导航/HUD | 开始/距离变化/环岛/结束 | 文字、HUD、地图各自有效；结束无残留 | 待实车 |
| 仪表像素 | 显示移除重建、原厂主题切换 | 不黑屏/遮挡原车告警，尺寸与窗口权限正确 | 待实车 |
| 地图开关 | 隐藏/显示、原厂HardKeyQuit | 只改变仪表输出，中控CarPlay继续 | 待实车 |
| 按键/焦点 | 短长按、电话、切歌、MODE、倒车打断 | 不把分类当DOWN/UP；倒车/E-CALL优先；释放/恢复正确 | 待实车 |
| 日夜 | 自动/强制浅深 × 灯开关 × 原厂主题 | 初始已开灯、unknown、重连均有合理显示 | 待实车 |
| 音频 | 音乐、导航、Siri、普通电话/微信语音 | 焦点/路由/麦克风/AEC正确；结束恢复，无A2DP双声 | 待实车 |
| 原厂歌曲/电话 | 元数据/来电覆盖导航后恢复 | 不把MediaSession快照当仪表输出，不重复电话生产者 | 待实车 |
| 首次无线 | 首装→连接→配对→GO→入网→首帧 | 每阶段有真实状态；拒绝权限可恢复；不要求手动建热点 | 待实车 |
| 网络回收 | 主动断开、手机离开/回来 | 仅回收本App临时组，唯一活跃会话，无失控重试 | 待实车 |
| 整车电源 | 冷启、短时熄火、真正休眠后唤醒 | 音视频/按键/Binder/显示恢复，休眠功耗与重试单独核实 | 待实车 |
| 厂商更新 | 校验后请求并等待实际包版本 | 正确固件/原厂服务签名；不可替换暂存；超时/恢复正确 | 本次未运行；有旧2731场景历史证据 |
| 官方Ultra | Apple授权协议、车辆资源/功能协商与iPhone端显示 | 完整官方协议和原生UI验收 | 未实现，不能以Android页面或主题接口代替 |

未知/待实现仍包括完整ECU/CAN/诊断数据库、RPM稳定App读取口、其他ADAS/车窗/制动等逐项能力、仪表歌词文本/时间轴、当前原厂歌曲输出桥、完整低层RPC载荷、MFi实际芯片/服务协议和Apple官方Ultra。全量目录中的同名声明不关闭这些验收项。
