2. 如何查一个接口

  1. 在 index.html 输入功能或名称，例如 空调、ICarATCManager、getCarSpeed、QisiMusicInfo。
  2. 优先看“接口声明”“回调合约”“SDK管理器”，必要时勾选包含生成辅助类/内部实现。*SDK 接口不是一定可直接 transact 的 Binder 合约。
  3. 查看准确类型、事务号、字段、常量与来源。空白事务号表示本次没有从相应 Stub 静态常量关联到编号，不能按列表顺序补号。
  4. 先核对目标版本和权限，再对照 Proxy/Stub 确定 Parcel 参数顺序、nullable 标记、返回类型、异常头、同步/oneway。完整目录不声称所有方法的 wire 格式已逐项审核。
  5. 在本手册中查已整理的调用条件、取值和生命周期。没有语义证据的接口保留原始值，不凭名称推测物理单位。

JSON/CSV 中的 Java 签名来自 DEX 描述符。泛型参数已被 DEX 类型擦除，通常只能看到 List/ArrayList；参数名和注释没有自动恢复。数据字段的排序是元数据顺序，不是 writeToParcel() 顺序。

3.2 正确的基本调用方式

普通同步 getter：writeInterfaceToken(模块descriptor) → 按 Proxy 顺序写参数 → transact(code,...,0) → 检查布尔返回 → readException() → 按类型读值。float 必须 readFloat()，不能读取为 int 后自行换算。

工作线程执行 Binder I/O；UI 线程只更新显示。可缓存仍存活的模块，服务死亡时清空并重绑。每个 Parcel 都在 finally 回收。分别处理 transact=false、空模块、descriptor 不匹配、SecurityException、DeadObjectException 和畸形/截断 reply。Binder 同步调用不能靠普通 Future 取消强行中断，应合并更新并避免无界堆积请求。

回调注册/注销通常写 StrongBinder，但每个接口独立核实。本包已审核的 ATC、SCCU、车辆状态回调 Proxy 使用 FLAG_ONEWAY=1、reply=null。接收端先 enforceInterface()，校验 payload 长度和区域索引，再更新状态；不是为所有其他厂商回调一律声明 oneway。

完整只读 Java 示例：Hs5ReadOnlyProbe.java。它接受已经绑定的根 Binder，仅提供车速原始值、挡位原始值和环境温度读取；不包含车控下发。

7. 当前 xcertplay 的应用层用法

本节 API 是当前项目进程内 Kotlin API，不是车机对外 HTTP 接口、导出广播或官方 Apple Ultra API。源码见 examples/xcertplay-vehicle。

// 宿主持有唯一 owner；宿主结束时关闭 observeHandle 和 lease。
val owner = Any()
val lease = Hs5VehicleData.acquire(context, owner)
val observeHandle = Hs5VehicleData.observe { snapshot ->
    val temperature = snapshot.value(Hs5VehicleField.AMBIENT_TEMPERATURE)
    // null 显示“未获取”；不要显示成 0°C。
}
// 不再需要时：
observeHandle.close()
lease.close()

观察者本身不保活连接。owner 按对象身份计数，同一个 owner 重复 acquire 不会新增一份所有权；保留首次返回的 lease 并明确释放。最后一个 owner 释放后注销回调、解绑并清空快照。观察通知回到主线程；底层 Binder 读取在工作线程。

快照连接状态有 STOPPED、UNSUPPORTED_DEVICE、CONNECTING、CONNECTED、UNAVAILABLE、PERMISSION_DENIED。snapshot.value(field) 只在连接有效、数值有限且样本年龄不超过 5 秒时返回值。轮询间隔 1 秒、车型/EOL 复核间隔 10 秒；这不是服务实时性能保证。重连按代次隔离旧回调和旧读取。

当前 32 字段：空调 10 项、环境温度 1 项、前排座椅 4 项、速度/挡位/燃油/低油量/续航/里程/油耗 7 项、四门 4 项、尾门 1 项、位置灯 1 项、四轮胎压 4 项。精确 enum 见 Hs5VehicleState.kt。

11. 无线、USB 与认证配置

3092 对照材料证实 p2p0（专用 Wi-Fi Direct）和 wlan0（普通 Wi-Fi）分开。wlan overlay 中 p2p_disabled=1 不能推出专用 p2p0 禁用。

当前 HS5 无线流程：点击连接 → 确认录音等必需授权 → 请求蓝牙可发现并等待状态 → 系统/iPhone 完成首次配对信任 → App 创建 P2P GO → 读取真实组信息 → iAP2 交给 iPhone → iPhone 加入 → AirPlay/CarPlay。iPhone 作为普通 Wi-Fi 客户端加入 GO，不要求使用 Android P2P 同伴发现界面。

  • Android9 WifiP2pManager.createGroup(channel,listener) 不接受自定义 SSID/密码/频率。读 requestGroupInfo / requestConnectionInfo 的实际结果；建组请求受理不等于 iPhone 入网。
  • 3092 对这三个 GO 操作只检查已声明 Wi-Fi 权限，未走扫描/定位门槛；requestPeers 是另一条扫描路径，不能外推。可选 GPS reporting 仍单独需要定位授权。
  • 3092 BluetoothAdapter.setScanMode(int,int) 为 public/light-greylist；当前请求120秒可发现，等待真实模式广播最多2秒，失败回退系统可发现确认页。返回 accepted 不等于射频模式已变。
  • API28 蓝牙使用安装时 BLUETOOTH/BLUETOOTH_ADMIN；Android12/13测试手机的 CONNECT/SCAN/ADVERTISE/NEARBY_WIFI_DEVICES 要独立判断。
  • 无线直连不需要 VPN/TUN。USB NCM 是另一条有线路径，VPN consent 不能套到无线说明。
  • 退出只移除 App 能证明自己持有的临时组，不清空用户或其他应用的网络组。

AppleFunction.conf 指向 /dev/i2c-0、地址0x10/0x11，并带 EXEED/Neusoft 等复用配置。这些不能证明主板已装 MFi 芯片。已核系统有 AppleServiceNative init/SELinux 残留，但未找到相应可执行文件；apple-server 的实际 Binder 协议未确认，不提供猜测事务号。访问 I2C 需 Linux节点权限、SELinux和真实服务共同允许；Manifest不能代替它们。carplay_data_file 是 SELinux 标签，不是独立分区。

当前使用项目既定认证后端；本手册不包含证书私钥、配对身份、OOB key 或 MFi 秘密材料，也未实现 Apple 官方 Ultra 协议。
