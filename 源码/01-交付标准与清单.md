# 本次源码交付标准与清单

本清单把“最新源码及文档”的交付要求落实为可检查项目。它是本次交付采用的核验标准；项目原有功能限制和外部验收项继续单独保留。

| 项目 | 交付要求 | 核验依据 |
|---|---|---|
| 最新性 | 从当前工作树提取，包含未提交及新增文件 | `SOURCE_PROVENANCE.json` 逐文件来源及原始哈希 |
| 可识别 | 明确组件、版本、包名、版本号及快照日期 | `VERSION.json`、`README-交付.md` |
| 完整源码 | 主源码、资源、Manifest、构建配置、测试、必要第三方源码与许可证齐全 | `manifest.json`、独立副本构建 |
| 可独立构建 | 三套工程不依赖原工作区的符号链接或本机路径 | 独立副本检查；服务端保留 `site/`、wrapper 和部署结构 |
| 构建及配置 | 写明 JDK／SDK／NDK、命令、输出路径和外部输入 | 每套 `docs/构建与配置.md` 或 `docs/构建部署与运维.md` |
| 架构及维护 | 说明模块职责、关键入口、主要数据链路和故障排查点 | 每套 `docs/架构与维护.md` |
| 接口及联调 | 说明授权、更新、包名／签名边界和上线前配置 | 服务端 `docs/API.md`、统一联调验收说明 |
| 可验证 | 区分本次运行、哈希一致复用、历史设备证据、尚未运行 | `verification.json`、统一验证报告 |
| 完整性 | ZIP CRC、归档内逐文件 SHA-256、解压后脚本核验 | [归档 SHA256SUMS.txt](交付归档/SHA256SUMS.txt)、各包 `manifest.json`、`verify_source.py` |
| 可移交 | 文档中的实际部署域名脱敏，本包已有文件链接改为相对路径 | `documentationAdapted` 标记 |
| 凭据边界 | 不含私钥、keystore、生产环境、缓存、构建输出和数据库 | 文件清单和内容扫描 |

## 每套目录

```text
组件源码包/
  README-交付.md
  VERSION.json
  SOURCE_PROVENANCE.json
  manifest.json
  verification.json
  verify_source.py
  docs/                  本次交付说明
  evidence/              相关已有验证及差异记录
  server|DiPlay|xcertplay/ 独立源码工程及原有文档
```

xcertplay 另附 `tools/source-only.init.gradle`，用于不注入认证身份的源码检查。它明确用于 CI／编译验证，产物不能当作可独立连接 iPhone 的车测包。正常车测构建仍执行工程原有认证文件准备任务。

服务端保留 7 个小型合成 APK 测试数据，用于签名、包名、版本和更新上传回归；它们不含运行认证身份，不能安装为产品。其余 APK、AAB、JAR 构建产物未纳入源码交付；Gradle wrapper JAR 属于构建工具，予以保留。

## 验收层次

源码交付验收检查文件完整、独立构建、测试结果和文档可操作性。产品上线还需要生产签名及配置、真实 PostgreSQL／Keycloak、NAS 运行版本、iPhone 和 HS5 的对应验收。源码交付完成不会把尚未实现的 Ultra、尚未接通的 xcertplay 服务或尚未运行的实车项目标为通过。

包内校验脚本允许构建后出现 `.gradle/`、`build/`、`local.properties` 等本机生成内容，但会检测交付源码和文档的缺失、修改或其他新增文件。首次解压时应先执行校验，再填入本地配置。
