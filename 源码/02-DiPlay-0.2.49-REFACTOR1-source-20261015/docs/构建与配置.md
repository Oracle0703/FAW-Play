# DiPlay 构建与配置

## 源码检查

先在包根目录执行 `python3 verify_source.py`。Android Studio 打开 `DiPlay/`；终端在该目录操作。准备 JDK 25、Android SDK Platform 37、NDK 28.2.13676358。通过 `ANDROID_HOME` 或本机 `local.properties` 设置 SDK；本机文件不进入源码清单。首次运行 wrapper 需要下载 Gradle 9.5.0 和依赖。

```sh
./gradlew :shared:testDebugUnitTest :common:testDebugUnitTest :mobile:lintDebug :mobile:assembleDebug -PfawLicenseDebug=false
```

Debug 输出为 `mobile/build/outputs/apk/debug/mobile-debug.apk`，包名 `com.shihab.diplay.hudtest`。源码检查模式明确关闭产品授权检查，不能作为正式授权产品分发。`-PfawLicenseDebug=true` 测试完整授权时仍需配套公钥和 Debug APK 签名摘要。

## 可独立连接的车测构建

由身份持有人准备外部目录：

```text
runtime-assets/
  offline-mfi/
    certificate.p7b
    identity.pk8
```

```sh
DIPLAY_AUTH_ASSETS_DIR=/absolute/path/to/runtime-assets ./gradlew :mobile:assembleStandaloneDebug
```

此任务会检查输入存在。不能把普通无身份 Debug 包当作完整车测安装包；上车前核对最终 APK 内两个指定 assets 与选择的输入一致。覆盖已装测试包可保留其设置和 Keystore 状态，前提是包名和签名兼容。

## Release 输入与构建

使用原有 `scripts/build-licensed-apk.py --help` 获取参数。该脚本负责读取外部口令文件、计算签名证书摘要、设置产品配置及调用 Release 检查；密钥和口令文件必须由持有人提供。

| 输入 | 用途 |
|---|---|
| `ANDROID_KEYSTORE_PATH`、`ANDROID_KEYSTORE_PASSWORD`、`ANDROID_KEY_ALIAS`、`ANDROID_KEY_PASSWORD` | APK 发布签名 |
| `DIPLAY_AUTH_ASSETS_DIR` | 运行配件认证身份 |
| `FAW_LICENSE_SERVER_URL`、`FAW_LICENSE_OIDC_ISSUER` | 产品 HTTPS 服务及身份 issuer |
| `FAW_LICENSE_PUBLIC_KEY_SPKI` | 产品票据／更新验签公钥 |
| `FAW_LICENSE_SIGNING_CERT_SHA256` | 固定当前 APK 发布证书摘要 |

公钥可从服务端持有人提供的公开 SPKI 文件读取；无需复制服务端私钥。独立服务端包里的 `secrets/` 是部署时生成的目录，未随源码交付。原有授权文档中的服务器相对路径应替换为实际的外部公钥文件路径。

Release 固定开启产品授权和 R8；`gradle/verify-license-release.gradle` 检查 HTTPS、公钥及实际 keystore 指纹。配置齐全后运行脚本，或按原文档执行 `:mobile:lintRelease :mobile:assembleRelease`。输出位于 `mobile/build/outputs/apk/release/`。本次没有生成新 Release；未来发布需递增版本，保留原证书并归档 mapping 和 APK 哈希。

## 安装及联调

真实 HS5 检查系统权限、蓝牙／Wi-Fi Direct、主屏、`Cluster-Display`、车辆音频、HUD 和方向盘接口。最低 API 28 不保证任意 Android 9 设备都具备 HS5 厂商接口。停车视频等车辆门禁必须继续要求新鲜有效状态。

更新需要同包名、兼容签名、更高版本及有效清单。安装权限取决于目标车机的系统接口或 Device Owner。故障复现应记录 APK 哈希、固件和 iOS 版本，区分构建成功、协议连通、音视频效果及生产授权四类证据。
