# DiPlay 架构与维护入口

源码基准目录为 `DiPlay/`。`mobile` 提供当前 HS5 APK 版本、Manifest 和打包入口；`common` 管原生首页／设置、权限、主屏与仪表窗口及车辆宿主交互；`shared` 管连接协议、媒体、认证、授权验签、更新协议和车辆输出。`automotive` 是独立 AAOS 入口；`samples/home` 与 `samples/maphost` 为样例。

| 路径／入口 | 维护职责 |
|---|---|
| `common/.../DiPlayActivity.kt`、`FawSettingsPage.java` | Launcher、首页与设置交互 |
| `common/.../CarPlayHostActivity.kt` | 主屏／仪表窗口、Surface、生命周期和连接宿主 |
| `common/.../DiPlaySessionService.kt` | 通知和进程内会话保活 |
| `shared/.../orchestration/CarPlayController.kt` | 无线连接、iAP2／AirPlay 交接、清理和恢复 |
| `shared/.../network/`、`transport/`、`iap2/` | Wi-Fi Direct、Bonjour、蓝牙／USB 与控制消息 |
| `shared/.../airplay/`、`media/` | 会话、流类型隔离、MediaCodec、AudioTrack 和麦克风 |
| `shared/.../hud/`、`common` 中的 Hongqi 类 | HUD、仪表提示／车道、方向盘及厂商界面接入 |
| `shared/.../licensing/`、`updates/` | 产品票据和更新清单的信任边界 |
| `common/.../LicenseActivity.kt`、`AppUpdates.kt` | 授权界面、更新检查和安装反馈 |

表中 `...` 表示 `src/main/java/com/shilapi/xcertplay`；实际包名配置由 mobile 构建文件决定。

启动后由宿主准备 Controller、媒体引擎、身份和车辆服务；无线 Wi-Fi Direct 与 Bonjour 就绪后，通过蓝牙 iAP2 引导 iPhone 加入网络，建立 AirPlay 配对和媒体会话，随后交接运行期控制隧道。音视频流进入 MediaCodec／AudioTrack；触摸、媒体键、麦克风及定位按各自通道回传手机。仪表视频与 HUD／车道元数据是不同路径，不能互相替代。

断开时先更新界面和会话状态，再撤销重试、清理媒体／网络及车辆输出。资源必须有明确会话归属，旧流、旧 Surface 和晚到回调不能释放新会话资源。后台保活不等于进程被杀后可自动重建全部连接。

当前相对旧 123 APK 的客户端变化集中在音频欠载后的缓冲恢复、小容量 AudioTrack 保护和失败渲染器重建。排查静置后卡顿先区分网络收包、视频输入／输出和实际屏幕提交；排查声音先区分媒体、导航、电话、Siri、焦点及原厂路由。设置参数应沿用现有状态／重连入口，避免在 UI 中另建协议或媒体对象。

修改协议／媒体时优先运行 `shared` 相关测试；修改设置、授权界面或宿主时运行 `common` 测试与 mobile lint。反射、JNI 和厂商接口变动要同时检查 R8 保留规则。正式回归仍需实际 Intel HS5 的解码、音频和权限证据。
