# 服务端构建、部署与运维

## 构建与检查

从包根目录进入 `server/`。安装 JDK、Python 3、Node.js；Gradle 使用包内 wrapper。数据库源代码目标 Java 17；本次本机通过 JDK 25 构建，Dockerfile 使用 Java 17。首次构建需下载 Gradle 和 Maven 依赖。

```sh
./gradlew -p authorization-server test bootJar
node --test authorization-server/scripts/test_admin_web.cjs authorization-server/scripts/test_web_api.cjs
python3 -m unittest discover -s authorization-server/scripts -p test_admin.py
```

测试默认使用 H2，不要求生产数据库及私钥。真实 PostgreSQL 测试使用 README 中的显式测试数据库和 reset guard；不能对生产库执行测试。`scripts/build_site.py` 是站点构建工具，按 `site/README.md` 使用；服务端 `bootJar` 会将当前站点静态文件并入 JAR。

## 新建本地环境

在 `server/authorization-server/` 中执行下列步骤，要求 Docker Compose 和 OpenSSL：

```sh
sh scripts/bootstrap-local.sh
docker compose up -d --build
curl --fail http://127.0.0.1:8080/health
```

bootstrap 仅用于新环境，会生成本地随机密码和服务签名密钥，并拒绝覆盖已有 `.env`。已有 NAS 的签名密钥不可用新生成密钥直接替换，否则既有客户端公钥及票据会失配。实际使用 NAS 自有 Compose／Lucky 代理时，按现有部署结构更新，不直接套用新建环境命令。

## 生产输入

| 类别 | 配置 |
|---|---|
| PostgreSQL | `DATABASE_URL`、`DATABASE_USER`、`DATABASE_PASSWORD`；Compose 使用自身数据库用户密码映射 |
| 管理身份 | `OIDC_ISSUER`、`OIDC_JWKS`、可选 `OIDC_AUDIENCE`；管理员需 `license-admin` 角色 |
| 授权签名 | `LICENSE_PRIVATE_KEY_FILE`、`LICENSE_PUBLIC_KEY_FILE`；客户端配置匹配的 SPKI 公钥 |
| 包名 | `LICENSE_ALLOWED_APP_IDS`，保留已有包名后按需增加 HS5 新包 |
| 更新 | `UPDATE_DIRECTORY`、`UPDATE_SIGNING_CERTIFICATES`，固定包名和发布证书 |
| HTTPS 模板 | `API_DOMAIN`、`AUTH_DOMAIN`、`TLS_EMAIL`；NAS 代理场景按实际配置 |

生产模板命令在配置完毕并完成检查后使用：

```sh
docker compose -f compose.yml -f compose.production.yml config
docker compose -f compose.yml -f compose.production.yml up -d --build
```

`config` 可能展开敏感值，应只在受控终端检查，避免保存进公开交付记录。服务端、客户端及 Keycloak 的 issuer、HTTPS 地址和 audience 必须对应。生产覆盖文件默认名单与基础文件不同，检查合并后的实际允许名单。

## 升级、备份和回退

升级前备份 PostgreSQL 中授权、设备、兑换码及审计数据，同时保留原 `.env`、签名密钥、更新目录、Keycloak 配置和当前镜像／JAR。备份不能随公开源码传递。Flyway 自动迁移到 V7；先在数据库副本验证迁移和旧票据续期。

更新后检查 `/health`、Flyway 版本、管理员登录、授权总数、码生成、扫码、续期、撤销／恢复、更新清单及下载。读到 health 为 ok 只确认应用响应，不代表所有外部服务联调通过。后台删除授权保留审计语义，已签发离线票据不能凭数据库删除立即远程失效。

回退前确认数据库迁移与旧程序兼容性。不能只回退 JAR 就假定数据库兼容；需要恢复数据库时，使用升级前一致备份，并记录升级期间新数据的处理。避免覆盖原更新目录和签名密钥。

## 诊断

401／403 优先检查 issuer、audience、JWKS 和管理员角色。新包无法激活时检查实际允许名单与包名。更新上传拒绝时检查证书固定值、包名、版本号、已存在同版本哈希及文件大小。授权异常时区分设备额度与累计首次激活次数；“永久购买”仍受离线票据期限限制。接口路径、字段和错误细节见 `server/docs/API.md` 与服务端 README。
